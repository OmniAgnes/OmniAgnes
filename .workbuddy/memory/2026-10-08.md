## 内置 git 工具（git / git_write）
- 需求：把 git 从裸 `bash` 提升为内置工具，解决脏输出污染会话、凭据交互挂起、破坏性命令不可控、输出未结构化四个坑。
- 新增 `internal/tools/git.go`，拆两个工具注册进 `builtinTools()`：
  - `git`（只读，plan 模式可放开）：status/log/branch/remote/diff/diff_stat/staged/show。
  - `git_write`（可写，plan 需审批）：add/commit(强制 -m)/push/restore。
- 关键设计：
  - **构造式白名单**：`gitOp.build` 拼参数数组（不拼字符串）→ 无 shell 注入；op 用 enum 约束。
  - **`GIT_TERMINAL_PROMPT=0`** 注入子进程环境：git 需凭据交互时不阻塞等输入（工具无 stdin 会挂到超时）；已配好的 wincred 凭据不受影响。
  - 复用 bash.go 的 `toUTF8`（GB18030 兜底）、`hasEnvKey`；路径安全走 Registry。
  - `argStringList` 兼容 `[]string` 与 `[]any`（真实 JSON 下是 []any）。
  - `gitBin()` 预留 `gitBinOverride` 全局可注入，供测试/将来打包自带 Git 时替换可执行路径。
- 测试：`internal/tools/git_test.go` 3 个用例（只读各 op、add→commit 往返、plan 只读护栏），全套 test 通过。
- **已提交**：`5b9d05e feat(tools): 新增内置 git / git_write 工具`，3 文件 +341 插入，已 push 到 origin/master（push 走代理成功；直连 github 会超时反推失败，应保持用沙箱代理 HTTPS_PROXY）。commit 仅含 builtin.go/git.go/git_test.go，npm 触发的 package-lock.json 改动与 .npm-cache/ 未入库。
- **已重编内核并启动桌面端**：`go build -o omni.exe .`（放到项目根，main.js 自动找 `webui/desktop/../../omni.exe`），桌面端用新内核启动成功（`--port 8791`，工作台 HTTP 200；MCP agnes/docx/mimo/pdf/pptx/xlsx「缺少 command」是本机 dev/ 未配置，非问题）。注意：桌面端工作目录默认是用户主目录 `~`（main.js `OMNI_CWD || app.getPath("home")`），不是项目目录。
- **前置结论（用户已确认理解）**：内置 git 工具仍依赖系统 PATH 里的 git，本地不装 git 用不了；不做"全自带"（go-git 会破坏 wincred 无感 push）。
- 附注：若做"完全自带 git"（不依赖系统 PATH），现实路线是打包 Git for Windows 便携版目录（体积 +~200MB，需随其 DLL/wincred），go-git 纯 Go 实现会破坏现有 wincred 无感 push 链路，不建议。

## 前端：项目内任务显示相对时间 + 抽公共时间工具
- 需求：项目（文件夹）里展开的任务列表，右侧也要显示最后更新时间（原先只有「任务」TAB 有）。
- 改法：

## 桌面端发版新增 Linux 支持（win/mac/linux 三平台）
- 需求：原来只发 Windows NSIS + macOS dmg，要加 Linux。**可行性已验证：Go 内核与 6 个 MCP 插件全部能交叉编译到 linux amd64/arm64**（无 cgo、无 windows-only 依赖；`gdiproc_windows.go` 有 `//go:build windows`，`capture_other.go` 是 `!windows` 且已含 linux 分支；`openBrowser`/打开文件夹等 `runtime.GOOS` switch 都有 default → `xdg-open`）。
- 改动 4 处：
  1. `webui/desktop/electron-builder.yml`：新增 `linux:` 段（target `AppImage` + `deb`，icon `build/icon.png`——Linux 不认 ico，category `Development`，`desktop.StartupWMClass: OmniAgens`）；extraResources filter 加 `!omni-linux-*` 排除交叉备料。
  2. `webui/desktop/scripts/electron-before-pack.cjs`：`PLATFORMS` 加 `linux: { pkg: "linux", kernel: "omni" }`；把散落两处的 `platform === "darwin"` 权限位判断收成 `NEEDS_CHMOD = new Set(["darwin","linux"])`（Linux 缺 x 位主进程 spawn 会被拒，同 mac）。
  3. `webui/desktop/main.js`：**GPU 兜底开关按平台分开**——原先 `if (env.OMNI_GPU !== "1")` 无条件关硬件渲染，那是 Windows 特有黑屏 bug 的补丁，照抄到 Linux 会让内置浏览器视频/滚动卡。改成 `forceSoftwareGL = win32 ? OMNI_GPU!=="1" : OMNI_GPU==="0"`（Linux 默认**保留**硬件加速，出问题用 `OMNI_GPU=0` 退回）；`disable-features CalculateNativeWinOcclusion` 只在 win32 加；`no-sandbox` 保留（AppImage 的 squashfs 带 nosuid，chrome-sandbox 本来就不可用）。
  4. `.github/workflows/release.yml`：新增 `build-linux` job（`ubuntu-latest`，`continue-on-error: true` 与 mac 同级），编 linux x64/arm64 内核 + `mcp-linux-<arch>/` 备料，`npx electron-builder --linux AppImage deb --x64 --arm64`，校验 ELF machine（`file -b` 匹配 `x86-64`/`aarch64`）+ x 位 + 插件齐全 + 4 个产物存在，上传 `omni-Setup-{x64,arm64}.{AppImage,deb}`。
  5. `webui/desktop/package.json`：加 `dist:linux` 脚本。
- 验证：yaml/js 语法全过；`GOOS=linux GOARCH=amd64|arm64 go build .` 成功（23MB/21MB ELF）；6 个 MCP 插件 linux/amd64 全编过；用假 packager 上下文实跑 beforePack（`arch:3` = arm64）确认换入的是 arm64 内核（size 与 arm64 备料一致、与 x64 不同）且插件被拷入。
- **待验证（CI 才能测）**：AppImage 实际打包、`StartupWMClass` 与桌面分类器图标名是否一致（不一致只是任务栏图标名不同，不影响启动）。

### v1.0.12 CI 失败与修复（commit a90f258）
- **现象**：build-linux job 在 electron-builder 起步阶段就失败：
  `configuration.linux.desktop should be one of these: null` + `must NOT have additional properties`。
- **根因**：`linux.desktop` 在 schema 里是 `anyOf[LinuxDesktopFile, null]`，而 `LinuxDesktopFile.additionalProperties = false`、只允许 `desktopActions` 与 `entry` 两个键。我平铺了第三个键 `StartupWMClass`，非法。
  **mac 之所以没事**：我只给 linux 段加了非法字段，mac/win 配置没动——所以这个坑只在新增平台时暴露。
- **修法（不止挪进 entry）**：读了 `node_modules/app-builder-lib/out/targets/LinuxTargetHelper.js` 的实现，发现 Electron 的 app_id 来自 `package.json` 的 `desktopName`，`StartupWMClass` 必须与之一致才能关联窗口；工具源码明确注释 `StartupWMClass doesn't work for unicode`，手填不可靠。
  最终改用官方机制：`package.json` 加 `desktopName: "OmniAgens"` + `electron-builder.yml` 的 `linux.syncDesktopName: true`，删掉手写的 `desktop` 段。
- **新增防线**：`webui/desktop/scripts/validate-builder-config.cjs`（`npm run check:config`），用 electron-builder 自带 `scheme.json` + ajv 静态校验配置；已加进 release.yml **三个 job** 的 electron-builder 步骤之前。
  **反向验证过它有效**：临时写入非法配置 → 脚本报 `must NOT have additional properties` + `params: {"additionalProperty":"StartupWMClass"}`，与 CI 日志完全一致；随后还原配置再跑恢复通过。
  反验证时踩了个小坑：第一次用 `node -e` 内联正则改文件，bash 把 `\n` 吞成字面 `n` 导致正则失效、脚本没真正测到。**改测试文件要写成独立的 .cjs 再 node 执行，别在 `-e` 里塞多行字符串。**
- **依赖声明**：`ajv` / `js-yaml` 原是传递依赖被 hoist，显式写进 desktop 的 devDependencies，并用 `npm install --package-lock-only` 同步 lock（这俩本就在依赖树里，只多了 3 行声明，无新包）。实测 `desktopName` 不需要进 lock（`npm ci --dry-run` 通过）。
- 提交 `a90f258`，push master 成功，本地与远程 HEAD 一致。
- **注意**：v1.0.12 这个 tag 已经打出去了，指向的是**有 bug 的配置**。修复在 master 上，需要重新发一个 tag（v1.0.13）才能让 CI 用上新配置。
