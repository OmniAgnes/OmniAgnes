## openrouter 503「无可用渠道」→ 加请求重试
- 现象：`provider openrouter 返回 503: 分组 default 下模型 qwen/qwen3.8-27b:free 无可用渠道（distributor）`。
- **排查结论：模型和key 本身没问题**。直连复测 `qwen/qwen3.8-27b:free` 与 `stealth/space-bunny-alpha` 都是 200；再分别测 stream=true / stream=false+max_tokens=8192 / stream=true+tools 全部 200。→ 是中转网关侧**瞬时渠道池抖动**（免费档渠道浅，其他 IDE 用量小能排上，omni 带完整历史+工具定义就挤不进去）。
- 真缺陷在代码：omni 撞 503 直接抛错，**零重试**。已在 `internal/llm/openai.go` 加：
  - `retryableStatus(code)`：只重试 429/502/503/504；**刻意不含 400/401/403/404**（配置或请求本身有问题，重试无意义且会掩盖 401）。
  - `doWithRetry(ctx, body, onEvent)`：最多 3 次，指数退避 1s→2s，`ctx.Done()` 可取消；可重试时排干并关掉旧 body 再重试。
  - `notifyRetry`：重试前发 `EventReasoning` 事件「[重试 n/3] 上游暂时不可用…」，否则长等待界面像卡死。
  - `httpError`：错误信息带上 `p.model` + `p.baseURL`，中转网关文案常不含 provider 名，之前分不清是哪条配置。
- `go build` + `go vet` + `go test ./internal/llm/` 全通过。

## 模型配置添加时自动填默认上下文/输出
- 需求：设置页「添加模型」时，自动写入 `context_window: 1000000`、`max_output_tokens: 128000`。
- 改法（`webui/frontend/src/components/SettingsDialog.tsx`）：
  - 顶部加常量 `DEFAULT_CONTEXT_WINDOW = 1_000_000` / `DEFAULT_MAX_OUTPUT_TOKENS = 128_000`。
  - `addModels()`（~L833）里为**新增**的模型名写 `model_options[m] = { context_window, max_output_tokens }`；已有条目不覆盖，优先沿用该供应商最后一个模型的既有值（`opts[cur[cur.length-1]]`），再回落默认常量。
  - 同时 `onChange({ models, model: models[0], model_options: opts })` 一起提交。
- 注意：`patchModelOptions` 里判定"全空就删条目"，所以默认值不能靠 UI 兜底，必须在 addModels 直接写进 model_options；`ModelOptionsRow` 的摘要行会自动显示「上下文 1000000 / 输出 128000」。

## ModelPicker 二级定位第三版（终版）：视口 clamp
- 第二版把 top clamp 到「一级面板高 − 二级高」是错的：二级和一级高度接近时 max≈0 → 二级永远贴顶（用户截图实锤）。
- **终版**（Flyout 内 useLayoutEffect）：用 `anchor.getBoundingClientRect()` 取选中行视口位置，`vpTop = 行中心 − 二级高/2`，按**视口** clamp（上下留 8px），再减 `fly.offsetParent.getBoundingClientRect().top` 转成相对偏移。offsetParent = 外层 absolute 弹层容器（dropUp 翻转时也正确）。
- 教训：**弹层跟随锚点定位一律用 getBoundingClientRect + 视口 clamp，别用 offsetTop 相对定位祖先再手动补 scrollTop，也别 clamp 到比自身矮的容器**。

## 修复 provider 401: User not found
- 现象：调用报 `provider 返回 401: User not found.`
- 根因：全局配置 `~/.config/omni/config.json` 里 `provider` 字段被写成 `"stealth/space-bunny-alpha"`（那是个**模型名**，不是供应商名），`internal/llm/resolve.go` 的匹配规则是`Provider.Model == target || HasModel(target)`，于是按模型名命中了 openrouter 那条；而 openrouter 的 key 已失效，返回 401。
- 逐个 provider 探测连通性：agnes / tokenrhythm / sensenova 全200，**只有 openrouter 401**。
- 修法（改配置，不改代码）：`provider` → `agnes`、`model` → `agnes-3.0-flash`，并把 openrouter 条目的 api_key 清空，避免再次误匹配。

**踩坑记住**：`cfg.Provider` 字段名是"供应商"但历史上被当成"当前模型名"用，`resolve.go` 也按模型名匹配。**以后手动改配置时 provider 要填供应商名（agnes），不要填模型名。**

## ModelPicker 二级面板跟随一级（已彻底重做）
- 需求：点开某个供应商后，二级模型列表的垂直位置要**从一级选中项的左侧出现**（垂直对齐该选中行），不能恒定 top-0、不能与一级高度一样。
- 第一版 `row.offsetTop - scroll.scrollTop` 是错的（一级面板自身是定位祖先，offsetTop 已相对它，多减一次 scrollTop 导致 top 算小、定位飘）；且第一次点击展开的 onClick 表达式错配，首次点击无效。
- **最终改法**（`ModelPicker.tsx`）：把一级选中行 `rowRefs.get(hoverProvider)` 作为 `anchor` 传给 `Flyout`；Flyout 内部用 `useLayoutEffect([anchor, models])` 算 `top = anchor.offsetTop + anchor.offsetHeight/2 - listH/2`（选中行中心对齐二级面板），clamp 到一级面板可视高度内。默认 anchor=null → top=0（顶对齐）。
- 一级行 button 始终挂 `ref={(el)=>{...rowRefs.current.set/delete...}}`。

## 401 的深层根因 & 防护
- `cfg.Provider` 会被应用/前端写回成**模型名**（如 `stealth/space-bunny-alpha`），而 `resolve.go` 按模型名匹配供应商 → 误中 openrouter（key 失效）→ 401。手动改配置 provider 字段会被再次覆盖。
- 最终在 `resolve.go` 加了防护：目标指向的供应商若 `ResolveAPIKey()==""` 且非 ollama/localhost → 跳过，回落 Default。同时配置里 openrouter.api_key 已清空。

## 消息流左边缘对齐：有图标的行不许有左边距
- 现象：AI 回复时，「工具调用 / 思考 / 处理中」这些**带图标的行**左边有 8px 缩进，而下方 Markdown 回复正文左边距是 0 → 两类行的左边缘不在一条竖线上，看着"上下没对齐"。
- 根因：这几行的容器都写了 `px-2`（Tailwind），而 `.md-output`（Markdown 正文）没有任何左内边距。
- 改法：把 `px-2` 全换成 `py-1 pr-2`（只保留右内边距）。涉及 4 处：
  - `Chat.tsx` `ProcessingIndicator` 根 div
  - `Chat.tsx` `ThinkingBlock` 的 `CollapsibleTrigger`
  - `ToolCallGroup.tsx` 的 `CollapsibleTrigger`
  - `ToolCallView.tsx` 的 `CollapsibleTrigger`，以及其下"你允许/拒绝了该操作"那行 `px-2.5` → `pr-2.5`
- **约定（记住）**：消息流里凡是带前置图标的行，左内边距一律为 0，只给右内边距。展开详情块（`ml-3`）是有意的层级缩进，**不要**一起去掉。
- 构建：vite build → `go build -o omni.exe .` → `cp omni.exe webui/desktop/bin/` 三步都走完。
