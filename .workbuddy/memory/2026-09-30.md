## 桌面黑屏根因与修复（07:00）
- 根因1：本机 GPU 进程反复崩溃（0xC0000005→FATAL "GPU process isn't usable"）。`app.disableHardwareAcceleration()` 单独不够，必须 `--disable-gpu` + `--disable-gpu-sandbox` 三连。

## 21:09 修复复制按钮点不到（hover 陷阱）
- 症状：用户气泡的复制按钮鼠标移上去才出现，但往按钮方向一移它就消失，点不到。
- 根因：按钮绝对定位在气泡**外部**（短消息 `top-full` 下方、长消息 `right-full` 左侧），
  只有 `group-hover:opacity-100` 生效；鼠标从气泡移向按钮时先跨出 group 边界，
  按钮立刻 `opacity-0` + `pointer-events-none`。且按钮带 `pointer-events-none` 时
  自身 :hover 根本不触发，无法自救。
- 修法（Chat.tsx UserBubble）：
  1. 按钮外套 `<span className="group/copy ...">`，去掉 `pointer-events-none` ——
     `opacity:0` 元素仍能接收指针事件，所以外层自身 hover 生效（`hover:opacity-100`），
     点进去也不会消失；另加 `focus-within:opacity-100`（键盘可达）。
  2. 加透明热区 `<span aria-hidden>`：长消息 `-right-1 inset-y-0 w-1`、短消息 `-top-1 inset-x-0 h-1`，
     向气泡方向延伸 4px 盖住 `mr-0.5`/`mt-0.5` 的 2px 缝隙，鼠标经过不断开 hover。
  3. 真正的 Button 内层 `pointer-events-auto relative shadow-sm`（relative 让 Button 盖在热区之上）。
- **通用教训**：hover 才浮现且浮在容器**外**的元素，必须 (a) 容器自身 hover 态可用，
  (b) 用透明伪元素/子元素桥接间隙。否则就是不可点的 hover 陷阱。

## 22:00 任务栏图标/标题仍显示 Electron —— 根因是 AUMID，不是窗口图标
- **上一轮修错了**：只改了 `BrowserWindow.setIcon` + 拦截 `page-title-updated`，那是**窗口**属性；
  用户右键任务栏看到的 "Electron" 名字+图标来自 **AppUserModelID(AUMID) 解析结果**，两者无关。
- **根因**：Windows 任务栏按钮的身份 = 进程 AUMID → 去开始菜单找带该 AUMID 的快捷方式。
  开发态进程是 `electron.exe`，文件描述与内嵌图标就是 "Electron" → 右键菜单永远显示 Electron。
  打包态 exe 由 electron-builder 写入版本信息，所以只有开发态有问题。
- **修法**：
  1. `app.setAppUserModelId("com.omni.desktop")`（win32，ready 之前）。
  2. 开发态往用户开始菜单 `%APPDATA%\Microsoft\Windows\Start Menu\Programs\omni.lnk`
     写快捷方式，带**同名 + omni 图标 + 相同 AUMID**（`shell.writeShortcutLink` 的
     `appUserModelId` 字段），Windows 据此解析出 "omni"。
  3. `electron-builder.yml` 补 `appId: com.omni.desktop`，让安装器快捷方式 AUMID 与之一致
     （否则任务栏分组/通知会错乱）。
- **⚠️ 踩坑：`shell.writeShortcutLink(path, "replace", opts)` 在文件不存在时返回 false**（与文档描述相反）。
  对照实验结论：`create`(2 参/3 参) ✓、`update`(文件不存在) ✗、`replace`(文件不存在) ✗、`replace`(已存在) ✓。
  正确写法：`create(opts) || replace(opts)`（先 create，已存在时 create 失败再 replace 覆盖，保证幂等 + 图标路径最新）。
- 排查手法：写对照实验脚本逐字段试（最小字段/加 icon/加 args/换目录），先排除"字段问题"再排除"环境问题"；
  又用 dangerouslyDisableSandbox 在沙箱外复跑确认**不是我的命令沙箱所限**，才定位到 API 语义。
- 顺带：`contextBridge` 暴露的 `window.omniDesktop` 对象在渲染层**冻结**，无法 monkey-patch 包装函数来记录调用；
  preload 里的 `console.log` 也不进主进程 stdout（isolated world）。要记录桩调用必须
  `ipcRenderer.send` 回主进程。判断功能是否真的被调用时别指望这两条路。
